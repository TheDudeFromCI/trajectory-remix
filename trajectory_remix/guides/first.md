# First trajectory: ticks and windows

Goal: append a user request, generate reasoning, then answer after the reasoning.
This small syntax exercise comes before the [parallel lesson](parallel.md).
Call `get_session` first. Add the latest `expected_revision` to each edit below,
and replace `$EOS` with that session's configured EOS spelling.

## 1. Create an empty draft and open three windows

```json
{
  "name": "create_trajectory",
  "arguments": {
    "sample_id": "first-steps"
  }
}
```

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "0",
    "event": {
      "op": "open",
      "window": "request",
      "window-type": "document"
    }
  }
}
```

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "0",
    "event": {
      "op": "open",
      "window": "reasoning",
      "window-type": "reasoning"
    }
  }
}
```

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "0",
    "event": {
      "op": "open",
      "window": "chat",
      "window-type": "chat"
    }
  }
}
```

All three windows open at the same tick. Each has its own history. Stay within
`max_window_slots`; ordinary windows must be opened before receiving content.

## 2. Insert the user's complete request

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "0",
    "event": {
      "op": "append",
      "window": "request",
      "source": "user",
      "content": "Say hello.",
      "loss": {
        "mask": "exclude"
      }
    }
  }
}
```

`append` inserts the whole block at that tick. It represents outside input, so
exclude it from training loss. The user message is not slowly generated by Kidra.

## 3. Generate reasoning and mark its last token

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "1",
    "event": {
      "op": "generate",
      "window": "reasoning",
      "content": "A short greeting answers the request.{N_TICK:1}"
    }
  }
}
```

`generate` emits one token per tick in this window. Tick 1 is its **start**,
not its whole duration. Tokens depend on the configured tokenizer; character
counts and word counts do not give the finish tick. `{N_TICK:1}` captures the
tick at that point in the stream and emits no text. Its ID is unique in this draft.

## 4. Answer after that mark, then close the other windows

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "{N_TICK:1}+1",
    "event": {
      "op": "generate",
      "window": "chat",
      "content": "Hello!{N_TICK:2}$EOS"
    }
  }
}
```

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "{N_TICK:2}+2",
    "event": {
      "op": "generate",
      "window": "reasoning",
      "content": "$EOS"
    }
  }
}
```

```json
{
  "name": "create_event",
  "arguments": {
    "sample_id": "first-steps",
    "tick": "{N_TICK:2}+2",
    "event": {
      "op": "generate",
      "window": "request",
      "content": "$EOS"
    }
  }
}
```

Generated EOS closes a window; finishing ordinary text does not. Keep information
windows open until the response that needs them has finished. Different windows
can emit their closing tokens at the same tick.

## 5. Check the result, then stop

Call `validate_trajectory(sample_id="first-steps")`. Expect `valid: true`; inspect
any diagnostics. Call `get_anchors` to see the actual ticks for marks 1 and 2.
Call `get_window_history` for `reasoning` and `chat`: check that the answer starts
after mark 1. Use `preview_snapshots` over a small range inside `0..max_tick`
from validation if you want to inspect visibility.
